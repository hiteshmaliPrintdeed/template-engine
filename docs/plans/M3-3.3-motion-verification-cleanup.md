## 4. Tasks

### Task 1 — Stage-mapped synthesis loader

Replace the flat bar in `App.jsx` with a 4-stage loader whose stages map to the **real** checkpoints already emitted by `process_async_job`, not a fully synthetic timeline:

| UI stage | Copy | Real `jobProgress` range | Rule |
|---|---|---|---|
| 1 | *Scanning visual balance, exposure & focal sharpness* | 0–20% | May animate freely while waiting; may only render "complete" once `jobProgress >= 20`. |
| 2 | *Curating 5-role semantic color harmonies* | 20–45% | Same rule at 45. |
| 3 | *DSA Solver computing golden-ratio double spread bounds* | 45–70% | Same rule at 70. |
| 4 | *Binding cover jacket & 300 DPI pre-flight quality check* | 70–100% | May only render "complete" once `job.status === 'completed'`. |

Within a range, interpolate smoothly (spring easing, `cubic-bezier(0.16, 1, 0.3, 1)`, minimum 250ms per visual tick) so the bar doesn't visibly jump 20→45→70→100. The hard rule — no stage renders "complete" ahead of its real checkpoint — is what keeps this an honest latency mask instead of a UI that can show "done" moments before a real failure surfaces. Add a live elapsed-time counter and a rotating micro-facts ticker; both are purely cosmetic and may run independent of real progress.

- `test_suggest_titles_without_key` — `GEMINI_API_KEY` unset, asserts fallback shape and sub-50ms wall time.
- `test_suggest_titles_caches_by_session` — two calls with the same `session_id` result in exactly one underlying AI/fallback invocation (mock-count assertion) — the regression test for the double-call cost fixed in [3.2 Task 2](M3-3.2-guided-story-studio.md#task-2--story_aipy-enable-gemini-bound-it-cache-it).

## 8. Risks & rollback

| Risk | Mitigation |
|---|---|
| Tying loader stages to real progress means a genuinely slow backend stage (e.g. a large Gemini prompt) shows a genuinely slow UI stage | That's the point — Task 1's rule exists specifically so the UI never lies about state. A slow stage should look slow, not jump ahead. |
| The new test file could pass "by accident" if its multi-chapter fixture never actually reaches the `ch_title` branch | Task 3 explicitly requires the fixture forces `len(macro_chapters) > 1`; assert the fixture's chapter count directly in the test setup as a guard on the guard. |
| Design-token sweep touches many small inline styles, risk of visual regression | Purely additive palette substitution — same layout, same components, only color values change. Visual diff in the manual UI audit (Task 5) is the catch-all. |

**Rollback:** each task is independently revertible; the test suite addition carries no runtime risk at all and can be kept even if a later change reverts the loader or token work.
