# Stage 1.6 — Fail honestly

**Milestone 1 · 0.5 day · No dependencies · `[MUST land before 1.7]`**

---

## 1. Objective

Remove every path that fabricates output when real data is missing. Today a job with zero resolvable photos produces a **complete photobook of stock placeholders** and reports success. This is the most dangerous behaviour in the codebase, and it must be gone before load testing — otherwise the load test passes while producing garbage.

Half a day. Do it in any spare slot, early.

---

## 2. Current state

### 2.1 The fake photobook

[`main.py:715`](../../backend/app/main.py), inside `process_async_job`:

```python
if not photos:
    logger.warning(f"[JobWorker] No matching photos in store for job {job_id}. Using multi-sample fallbacks.")
    photos = [
        PhotoMeta(id="sample_1", filename="sample1.jpg", url="/uploads/sample1.jpg", ...),
        PhotoMeta(id="sample_2", ...),
        PhotoMeta(id="sample_3", ...),
        PhotoMeta(id="sample_4", ...),
    ]
```

Execution then continues normally: themes are generated, layouts solved, three variations returned, job marked `completed`. The user sees a finished photobook. They can export it to PDF and pay to print it.

**This has already happened in production.** From [`docs/incidents/2026-08-21-generate-async-race.md`](../incidents/2026-08-21-generate-async-race.md):

```
[JobWorker] Starting job job_a08867d1 for prompt: 'Friends at ISKCON Temple' with 0 photos.
[JobWorker] No matching photos in store for job job_a08867d1. Using multi-sample fallbacks.
```

The real fault was an ingest race — photos arrived after generation started. The fallback converted a fixable timing bug into a silently wrong product, and the log line was the only evidence.

### 2.3 Two more placeholder paths

- [`solver.py:79`](../../backend/app/engine/solver.py) — `cover_img = photos[0].url if photos else "/uploads/sample_placeholder.jpg"` (also handled in [1.5](M1-1.5-covers-variations.md)).
- [`pdf_exporter.py:106`](../../backend/app/engine/pdf_exporter.py) — `return UPLOADS_DIR / "sample_placeholder.jpg"` when an original can't be resolved. **This one silently degrades a paid print export**, substituting a placeholder for a real photo in the PDF.
- [`main.py:362`](../../backend/app/main.py) — `PhotoMeta(id="p1", url="/uploads/sample_placeholder.jpg", ...)` in a reshuffle path.

### 2.4 Why this blocks Stage 1.7

The load test asserts that 20 × 1,000 photos produce correct albums. With the fallback in place, a session that loses all its photos to a race, a cache eviction, or a session-ID mismatch still returns three complete variations and a `200`. **The load test would report success on total data loss.** Every failure mode Stages 1.1–1.4 exist to fix would be invisible.

## 4. Tasks

### Task 1 — Fail the job

Replace [`main.py:715-738`](../../backend/app/main.py):

```python
if not photos:
    logger.error(
        f"[JobWorker] Job {job_id} resolved 0 photos from {len(photo_ids)} requested IDs "
        f"(session={session_id}). Failing job."
    )
    await _fail_job(
        job_id,
        "No valid photos found for this session. "
        "Photos may still be uploading, or all were rejected during quality filtering.",
        error_code="NO_PHOTOS",
    )
    return
```

`_fail_job` sets `status="failed"`, `progress=100`, persists via `SessionStore.save_job()`, and returns. No fabrication, no partial book.

Add a **partial-loss** guard too — silently dropping 40% of a user's photos is nearly as bad as dropping all of them:

```python
resolved_ratio = len(photos) / max(1, len(photo_ids))
if resolved_ratio < 0.9:
    logger.warning(
        f"[JobWorker] Job {job_id} resolved only {len(photos)}/{len(photo_ids)} "
        f"({resolved_ratio:.0%}) photos — possible ingest race or eviction."
    )
```

Below 50%, fail rather than warn. A half-empty album is not the product.

### Task 2 — Fix the race this was masking

The `NVM.md` incident was `/api/generate-async` firing before ingest finished. The current mitigation is a client-side spin in [`App.jsx:179`](../../frontend/src/App.jsx):

```js
for (let i = 0; i < 40; i++) {          // wait up to 8 seconds for ingestion
  if (uploadedPhotosRef.current.length > 0) { ... break; }
  await new Promise(r => setTimeout(r, 200));
}
```

A fixed 8-second client-side guess. With [Stage 1.1](M1-1.1-session-continuity.md) there is a real session state to check — enforce it server-side:

```python
@app.post("/api/generate-async", status_code=202)
async def generate_async(payload: GenerateVariationsRequest, background_tasks: BackgroundTasks):
    session = SessionStore.get_session(payload.session_id)
    if not session:
        raise HTTPException(404, "Unknown session.")
    if session["status"] == "ingesting":
        raise HTTPException(409, {
            "error": "ingest_incomplete",
            "received": session["received_photo_count"],
            "expected": session["expected_photo_count"],
            "message": "Photos are still uploading.",
        })
    if session["survived_photo_count"] == 0:
        raise HTTPException(422, {
            "error": "no_surviving_photos",
            "message": "All uploaded photos were rejected during quality filtering.",
        })
```

Then delete the client-side spin loop. The frontend disables the generate button until the session reports `ready`, which is both correct and better UX than an invisible 8-second wait.

### Task 3 — Delete placeholder generation

- Delete `ensure_sample_placeholders()` and its module-scope call from [`config.py`](../../backend/app/config.py).
- Delete the generated files: `backend/app/uploads/sample*.jpg`.
- Delete the reshuffle placeholder at [`main.py:362`](../../backend/app/main.py); return `422` when there are no photos to reshuffle.

Removing the import-time side effect also stops 15 file writes on every test collection.

### Task 4 — Make PDF export refuse to substitute

[`pdf_exporter.py:106`](../../backend/app/engine/pdf_exporter.py) currently returns a placeholder path when an original is missing. Raise instead:

```python
class MissingOriginalError(Exception):
    def __init__(self, photo_id: str):
        self.photo_id = photo_id
        super().__init__(f"Original file unavailable for photo {photo_id}")
```

Catch it at the endpoint and return `409` naming the outstanding photos — which composes with the export gate in [Stage 1.3](M1-1.3-storage-offload.md) Task 4:

```python
except MissingOriginalError as e:
    raise HTTPException(409, {
        "error": "originals_pending",
        "photo_id": e.photo_id,
        "message": "High-resolution files are still uploading. Please retry shortly.",
    })
```

**A print export must never silently substitute a placeholder for a customer's photo.** This is the difference between a delayed order and a refunded one.

### Task 5 — Surface failures in the UI

[`App.jsx:224`](../../frontend/src/App.jsx) `pollJobStatus` handles `completed` but treats `failed` thinly. Render the real message:

```js
if (job.status === "failed") {
  clearInterval(interval);
  setIsLoading(false);
  setStep('chat');
  setErrorBanner({
    title: "We couldn't build your album",
    message: job.message,
    action: job.error_code === 'NO_PHOTOS' ? 'Upload photos again' : 'Try again',
  });
}
```

Also replace the blocking `alert()` calls at [`App.jsx:168`](../../frontend/src/App.jsx) and [`PhotoUploader.jsx:30`](../../frontend/src/components/PhotoUploader.jsx) with the same inline banner — a modal `alert` in the middle of a 1,000-photo upload halts the JS event loop until dismissed, which can itself break the upload.

## 6. Test plan

**Unit**
- `process_async_job` with `photo_ids=[]` → job `failed`, `error_code="NO_PHOTOS"`, **no variations**.
- Job resolving 40 of 100 photos → `failed` (below 50% threshold).
- Job resolving 95 of 100 → completes, logs a warning.
- `pdf_exporter` with a missing original → raises `MissingOriginalError`, does not return a placeholder path.
- `generate_async` on an `ingesting` session → `409` with counts.

**Integration**
- Submit a job with nonsense photo IDs → `failed` with a readable message; no PDF produced.
- Export before originals finish → `409`, not a placeholder PDF.

**Grep gates**
```bash
grep -rn "sample_1\|sample_2\|sample_3\|sample_4\|sample_placeholder" backend/app/   # → empty
grep -rn "ensure_sample_placeholders" backend/                                        # → empty
grep -rn "alert(" frontend/src/                                                       # → empty
```

## 7. Exit criteria

- [ ] Zero resolvable photos → job `failed` with an actionable message.
- [ ] No code path substitutes a placeholder for a real photo.
- [ ] PDF export raises rather than silently substituting.
- [ ] The three grep gates above return nothing.
- [ ] `app.config` import performs no filesystem writes.
- [ ] Failures render as an inline banner, not a blocking `alert()`.
- [ ] The generate button is disabled until the session reports `ready`.

## 8. Risks & rollback

| Risk | Mitigation |
|---|---|
| Users now see failures that were previously hidden | That is the point. Those sessions were already broken — they were being shown a fake book. The message tells them what to do. |
| Removing the 8-second spin exposes a real race | Task 2 replaces a client-side guess with a server-side check on authoritative session state. Strictly stronger. |
| Demo breaks if something upstream fails | A demo showing a placeholder album is worse than one showing an honest error. Fix the upstream cause; that's Stages 1.1–1.4. |
| Some other code path depends on sample files | The grep gates catch it. Only `config.py` writes them and only the fallbacks read them. |

**Rollback:** deletions only, all independently revertible. There is no scenario where restoring the fallback is the right call — if it fires, the correct response is to fix what made photos unresolvable.

---

## 9. Why half a day is worth it

Every stage that follows depends on failures being visible. Stage 1.1 tests session continuity, 1.2 tests the data contract, 1.7 tests the load target — and all three are asserting that photos flow correctly end to end. A fallback that manufactures a plausible-looking album when photos are missing defeats every one of those assertions simultaneously. This is not cleanup; it is the precondition for the rest of the milestone being measurable.
