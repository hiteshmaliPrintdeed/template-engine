# Stage 3.2 — Guided Story Studio & Gemini title engine

**Milestone 3 · ~4–5 days · Depends on [3.1](M3-3.1-cleanup-declutter.md)**

---

## 1. Objective

Replace the deleted chat-bubble widget with a center-stage, multi-stage configuration studio, and give it a real backend contract: user-chosen or AI-suggested cover titles, and a genuine choice between narrative captions and photo-only layouts — enforced all the way through the DSA solver, not just at the API boundary.

This is also where `ENABLE_GEMINI_API` goes live for the first time, so this stage carries the AI-cost and latency risk for the whole PRD. See [Risks & rollback](#8-risks--rollback).

---

## 2. Current state

### 2.1 No content-preference contract exists

`GenerateVariationsRequest` ([`photobook.py:141-146`](../../backend/app/schemas/photobook.py)) carries only `photo_ids`, `user_prompt`, `session_id`. There is no `custom_title`, `include_text`, or `subtitle` anywhere in the schema, the endpoint, the job worker, or the solver.

### 2.2 The solver has an untested second caption source

[`solver.py:89-94`](../../backend/app/engine/solver.py):
```python
for c_i, chunk in enumerate(photo_chunks):
    if c_i == 0 and ch_title and len(macro_chapters) > 1:
        caption = ch_title.upper()
    else:
        caption = captions[(spread_idx - 1) % len(captions)]
```
Two independent sources feed `caption`: the per-chapter title (`ch_title`) and the rotating caption list. A naive "photo-only" patch that only touches the `else` branch — which is how an earlier draft of this PRD specified it — leaves the chapter-title branch able to inject a caption regardless of any content-mode flag. **This is the single most important correctness detail in this stage**, because it silently violates the "zero text frames" guarantee the whole photo-only feature exists to provide.

Downstream, `has_left_text = bool(caption)` at [`dsa_solver.py:418`](../../backend/app/engine/dsa_solver.py) already does the right thing once `caption` is actually empty — that machinery needs no changes.

### 2.3 `generate_photobook_variations_engine` has no room for these fields

```python
def generate_photobook_variations_engine(
    photos: List[PhotoMeta],
    ai_batch_result: Dict[str, Any],
    variant_seed_offset: int = 0
) -> List[PhotobookVariation]:
```
([`solver.py:29-33`](../../backend/app/engine/solver.py)) — no `custom_title`/`include_text`/`subtitle` parameter exists to thread through from the request.

### 2.4 `process_async_job` doesn't persist content preferences anywhere

[`main.py:1547-1552`](../../backend/app/main.py) takes `job_id, photo_ids, user_prompt, session_id` and nothing else. Whatever a user picks in the Studio has nowhere to live once the job is queued — which matters the moment reshuffle re-enters the picture (Task 7 below).

### 2.5 Reshuffle is a second, un-guarded code path

`POST /api/variations/reshuffle` ([`main.py:762`](../../backend/app/main.py)) and `POST /api/spreads/reshuffle` (called from [`SpreadViewer.jsx:57`](../../frontend/src/components/SpreadViewer.jsx), retained per 3.1) both regenerate layout content independent of the original `generate-async` call. Neither receives or looks up `include_text`/`custom_title` today. Left unaddressed, a user who chooses "Photo-Only" and then reshuffles a spread — a supported, retained interaction — silently gets captions back.

### 2.6 Gemini is fully wired but switched off, at a stale model reference

`ENABLE_GEMINI_API = False` is hardcoded at [`story_ai.py:236`](../../backend/app/engine/story_ai.py) (tracked as parked work in [`ROADMAP.md`](../../ROADMAP.md): *"Turn Gemini on properly ... using the 2-tier chapter-summary prompting already sketched in its docstring, keeping the local rules engine as a live fallback"*). The model actually configured in both the `google.genai` and legacy `google.generativeai` call paths is `gemini-3.5-flash-lite` ([`story_ai.py:300,318`](../../backend/app/engine/story_ai.py)) — this is current, correct, and must not be reverted to any earlier model name from a stale spec.

There is no timeout on either Gemini call path — an unresponsive endpoint hangs the request instead of falling back.

## 3. Target state

- `GenerateVariationsRequest` carries `custom_title`, `include_text`, `subtitle`; a new `SuggestTitlesRequest`/`SuggestTitlesResponse` pair backs a dedicated title-brainstorm endpoint.
- Choosing "Photo-Only" produces **zero** `type == "text"` slots across every spread of every variation, including chapter-opening spreads — verified by an automated test, not a manual read-through.
- A custom title, once chosen, applies identically to all three variations' `cover_title`.
- Reshuffling — either a whole set of variations or a single spread — preserves whatever content mode and title the user chose at generation time, because both are persisted server-side against the session and read back, not re-derived from the client on every reshuffle call.
- Gemini is live behind the existing `GEMINI_API_KEY` env var (unset ⇒ same fast local fallback as today, in any environment not ready for live AI calls), on a bounded timeout, and costs exactly **one** Gemini call per session — not two — even though the Studio and the generation job both need AI-derived content.
- The chat-bubble UI is gone (per 3.1); in its place, a four-stage center-stage configurator.

## 4. Tasks

### Task 1 — Schemas

[`backend/app/schemas/photobook.py`](../../backend/app/schemas/photobook.py):
```python
class GenerateVariationsRequest(BaseModel):
    photo_ids: List[str]
    user_prompt: str = ""
    session_id: Optional[str] = None
    custom_title: Optional[str] = None
    include_text: bool = True
    subtitle: Optional[str] = None

class SuggestTitlesRequest(BaseModel):
    user_prompt: str = ""
    session_id: Optional[str] = None
    photo_count: Optional[int] = 0

class SuggestTitlesResponse(BaseModel):
    titles: List[str]
    subtitles: List[str]
    category: str
    suggested_captions: List[str]
```

### Task 2 — `story_ai.py`: enable Gemini, bound it, cache it

- Flip the flag: `ENABLE_GEMINI_API = bool(GEMINI_API_KEY)`.
- Add an explicit timeout (6s) to both the `google.genai` client call and the legacy `google.generativeai` fallback attempt, so an unresponsive endpoint degrades to the local heuristic instead of hanging the request.
- Add `suggest_creative_titles(user_prompt, photo_count, session_id)`. On success, persist its result into `SessionStore` keyed by `session_id`.
- Update `generate_story_theme_batch(user_prompt, total_photos, session_id=None)`: if a cached `suggest_creative_titles` result exists for `session_id`, reuse its `category`/`captions` instead of issuing a second Gemini call. This is the fix for the double-call cost in §2.6 — one AI call per session, covering both the Studio's title brainstorm and the final generation job.
- Update `get_fallback_ai_response` to accept and apply `custom_title`/`include_text`/`subtitle` when building each variation dict, so the offline path honors the same contract as the live path.
- Replace the literal `"iskcon"`/`"temple"` string checks in `get_fallback_ai_response` with the existing `CATEGORY_THEMES_MAP` taxonomy (Travel, Celebration, Family, Milestones, Portraits, Memories) as the sole classifier — the taxonomy already covers this, only the ISKCON-specific literal needs to go.

### Task 3 — `main.py`: new route, threaded fields, persisted preferences

- Add `POST /api/chat/suggest-titles`, calling `suggest_creative_titles`.
- Extend `process_async_job(job_id, photo_ids, user_prompt, session_id=None, custom_title=None, include_text=True, subtitle=None)`; persist these three fields via `SessionStore.save_job(..., session_id=...)` alongside the job record, so they survive for reshuffle to read back (Task 7).
- Update `/api/generate-async` to pass `payload.custom_title`, `payload.include_text`, `payload.subtitle` into `background_tasks.add_task(process_async_job, ...)`.

### Task 4 — `solver.py`: gate both caption sources, thread the new params

Replace [`solver.py:89-94`](../../backend/app/engine/solver.py):
```python
if not include_text:
    caption = ""
elif c_i == 0 and ch_title and len(macro_chapters) > 1:
    caption = ch_title.upper()
else:
    caption = captions[(spread_idx - 1) % len(captions)]
```
`include_text` must be the first, outermost condition — not folded only into the `else` branch. This is the fix for §2.2.

Extend the signature:
```python
def generate_photobook_variations_engine(
    photos: List[PhotoMeta],
    ai_batch_result: Dict[str, Any],
    variant_seed_offset: int = 0,
    custom_title: Optional[str] = None,
    include_text: bool = True,
    subtitle: Optional[str] = None,
) -> List[PhotobookVariation]:
```
Apply the title override uniformly, in the loop that currently sets `cover_title` at [`solver.py:120`](../../backend/app/engine/solver.py):
```python
cover_title=(custom_title.upper() if custom_title else var_info.get("cover_title")) or "YOUR PHOTOBOOK",
cover_subtitle=subtitle or var_info.get("cover_subtitle") or "A COLLECTION OF MEMORIES",
```
for **all three** variations, not just the first.

### Task 7 — Reshuffle persistence (closes the gap in §2.5)

## 6. Test plan

**Unit / integration** (new file, see [3.3](M3-3.3-motion-verification-cleanup.md) for the full suite)
- `suggest-titles` without `GEMINI_API_KEY` → fallback shape, fast.
- `suggest-titles` called twice with the same `session_id` → exactly one underlying AI/fallback invocation (mock-count assertion) — proves the caching fix in Task 2.
- `generate_photobook_variations_engine(..., include_text=False)` against a multi-chapter photo set (forcing the `ch_title` branch to be reachable) → **zero** `type == "text"` slots anywhere, including chapter-opening spreads. This must fail against the unpatched `solver.py` and pass after Task 4 — it is the direct regression test for §2.2.
- `custom_title` applied → all 3 variations' `cover_title` match, not just variation 1.
- Reshuffle a `include_text=False` job → result is still caption-free, without the client sending `include_text` on the reshuffle call.

**Manual**
- With no `GEMINI_API_KEY` set, walk the full Studio flow and confirm `suggest-titles` returns instantly with sensible fallback titles.
- With a real key set in a non-production environment, confirm real Gemini titles return within the 6s budget and the studio doesn't hang if the network is slow.

## 8. Risks & rollback

| Risk | Mitigation |
|---|---|
| This is the first time the app makes live Gemini network calls on the hot generation path | Gated behind `GEMINI_API_KEY` being set at all — any environment that isn't ready simply doesn't set it, and gets the existing fast local engine unchanged. Bounded by a 6s timeout with a tested fallback. |
| Live Gemini cost/latency is unverified beyond this stage's manual check | Stage [3.3](M3-3.3-motion-verification-cleanup.md) adds a dedicated real-key latency verification step before this is considered production-ready. |
| The chapter-title caption branch is easy to miss if this stage is implemented from memory rather than from this doc | The corrected code block in Task 4 gates `include_text` as the outermost condition; the regression test in the test plan fails on the naive (else-only) patch by construction. |
| Reshuffle persistence adds a `SessionStore` read on every reshuffle call | Already an existing dependency (`SessionStore.get_session_photos`, `SessionStore.save_job`) — no new infrastructure, just one more field read from an existing lookup. |

**Rollback:** the schema/endpoint additions are additive (`Optional`/defaulted fields) and safe to revert independently of the solver fix; the solver fix and the reshuffle persistence fix should be reverted together with the frontend Studio, since none of the three is independently useful without the others.
